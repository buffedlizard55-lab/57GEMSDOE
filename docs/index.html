Why the previous download was rejected

The portal said “Predicted values must be in range [0, 1]”. The sample submission in this repository (data/bridge/, see IR-57-BRIDGE-01) carries nodata = NaN and 7,111,787 NaN cells outside the study-area footprint. Working hypothesis (not proven, see IR-57-NAN-02): a range check that reads NaN as failing v >= 0 and v <= 1 would reject a file written with that convention, even though every value inside the footprint is a legal 0 or 1.

Fix: write every one of the 12,279,160 cells as a finite float in [0, 1], set the outside-footprint cells to 0.0, and write no nodata tag. That is exactly what mode="zeros" in src/gems57/grid.py does. Registered as IR-57-NAN-01.

What the score means

The metric is the distance-weighted Tversky index with α = 0.2 (false positives), β = 0.8 (false negatives) and a 300 m triangular kernel. False negatives are weighted four times more heavily than false positives, so the metric rewards covering real fault pixels over being conservative — but every dot still costs 0.2 in the denominator, so the allocation is fitted rather than sprayed.
