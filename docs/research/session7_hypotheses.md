## What the reported 0.2778 does—and does not—tell us

The repository's audit measures the GEMSDOE32-labelled 0.2778 raster as an exact subset of the GEMSDOE28-labelled 0.2708 raster: it removes 2,545 dots and adds none, with every removed dot 1.41–2.00 px from the bridged mapped catalogue. That suggests a precision mechanism worth testing because DTI penalizes false positives more heavily than false negatives. It does **not** establish that this pruning caused the reported score change: both scores are **OWNER-REPORTED**, not exact-file `ORGANIZER-CONFIRMED` receipts, and the public leaderboard is not a file-to-score receipt. The saved public-board snapshot retrieved 2026-10-10 lists 0.3774 at rank 1, 0.3195 at rank 8 and 0.2778 at rank 22; it is a dated, selected-row snapshot, not a live guarantee.

Sources/evidence: [file-level measurement](../data/session6_mechanism_and_witness.json), [leaderboard snapshot](../data/leaderboard_snapshot.json), [official leaderboard](https://www.drivendata.org/competitions/306/competition-doe-gems/leaderboard/), [organizer's exact-known-fault-mask clarification](https://community.drivendata.org/t/scoring-clarification-are-known-usgs-ingenious-faults-masked-when-scoring-and-are-they-in-the-final-round-label-set/11516/4), and [organizer's definition of new fault geometry](https://community.drivendata.org/t/where-do-you-draw-the-line/11536/2).

**No causal or score projection is made.** A hide-and-recover test uses withheld *catalogued* components as a proxy for new strands; it cannot establish live/private performance or determine which team's file produced a public score.

## Pre-registered S7-1 experiment

- **Top candidate at branch-local registration:** S7-1 (previously listed as H6-1; the registration believed it had not yet been validated in this checkout). A post-run cross-branch audit found an H6-1 matched-pruning holdout had already merged to main; see the correction below. The existing catalogue, sample grid and local CSV are bridge data; their hashes verify those local bytes, not independent official-origin authenticity.
- **Holdout:** shared `buffered_component_draw` / `gems57-pooled-hide-v2`, seed 20; whole components withheld; 3-pixel feature-context buffer; catalogue features computed only from visible traces; known visible catalogue masked pixel-exactly at scoring.
- **Fitting/emission:** train-only host-anatomy fit and train-only prevalence/zone determine the dot cap. The intervention prunes exactly those base dots within 2 pixels of the visible catalogue; a fold-seeded random prune removes the same number. No hidden/test-positive count is used to choose locations or budgets.
- **Controls:** unchanged base anatomy and matched-random removal. Paired bootstrap resamples the shared physical 20 km blocks. Report all numbers as `HOLDOUT-DTI` with evaluator version, withheld-positive count and 95% CI.
- **Leakage canary:** run every feature alone with discriminative AUC `max(AUC, 1−AUC)`. Any value >0.90 blocks interpretation.
- **Promotion:** no slot is used. A research candidate would need a strictly positive paired lower 95% bound vs matched random and must not be represented as beating the existing current HOLDOUT-DTI best unless it actually does under a comparable evaluator and split.
- **Uniqueness:** the inherited literal registry gate is checked before production placement and again on final dots. The current saved 696-raster audit contains a verified universal-support witness; a full registry refresh is required before any future candidate. If the literal gate fires, record the duplicate and stop. No exemption, threshold or registry-classification change is made here.

## Session 7 observed result — negative against matched random

**Evidence class:** `HOLDOUT-DTI`, evaluator `gems57-pooled-hide-v2`, seed 20, 11,321 withheld positive pixels, pooled α=0.2 / β=0.8 / 300 m triangular kernel, 1,000 paired spatial-block draws, four buffered whole-component spatial folds.

| Arm / paired contrast | DTI [95% CI] |
|---|---:|
| Base anatomy allocation | 0.100989 [0.085568, 0.117643] |
| S7-1 proximal prune | 0.101005 [0.085576, 0.117672] |
| Equal-count random prune | 0.101007 [0.085579, 0.117665] |
| Proximal − base | +0.0000158 [0.0000032, 0.0000352] |
| **Proximal − matched random (pre-registered test)** | **−0.0000020 [−0.0000156, +0.0000165]** |

The target prune removed only 15 of roughly 36,000 emitted base dots across folds (9, 0, 5, 1). Although proximal pruning is fractionally above the unchanged base, it is marginally below the equal-count random control and the paired 95% interval crosses zero. The hypothesis is **not supported**; no threshold sweep or follow-up arm was run. The clean feature canary had maximum discriminative AUC 0.825867; this is a leakage screen, not evidence of live generalization.

The saved prior best (0.141391 [0.124513, 0.161457], 11,321 positives) has a different `evaluate_holdout.py` hash despite the same version string, seed and split. The numerical difference is therefore not a valid promotion comparison; the report labels it historical only and does not claim a comparable best was beaten. Since the matched-random condition failed, and the current-best comparator is not implementation-identical, S7-1 is not promoted.

## Current data boundary and source references

- S7-1 used only bridged catalogue geometry and the shared evaluator; it did not read or rebuild the 19-band feature stack. The availability of that stack changed in a concurrent main-branch data-preparation PR and is irrelevant to this geometry-only result.
- The competition target is fault presence, not direct geothermal vent, reservoir or heat-flow labels. See the official [problem description](https://www.drivendata.org/competitions/306/competition-doe-gems/page/967/) and [about page](https://www.drivendata.org/competitions/306/competition-doe-gems/page/968/).
- Scientific framing is limited to the source audit already recorded in [`evidence/source_checks.json`](../data/source_checks.json): [Schreurs (2003)](https://www.lyellcollection.org/doi/abs/10.1144/GSL.SP.2003.210.01.03), [Tchalenko (1970)](https://pubs.geoscienceworld.org/gsa/gsabulletin/article-abstract/81/6/1625/6891/Similarities-between-Shear-Zones-of-Different), [Savage & Brodsky (2011)](https://agupubs.onlinelibrary.wiley.com/doi/full/10.1029/2010JB007665), and the [Faulds, Henry & Hinz bibliography](https://nbmg.unr.edu/staff/faulds.html). The stored audit documents which records/abstracts were retrieved; it does not claim full-paper review or independent proof that a particular mapped line is a fault.

**Non-fault mimics:** map generalization and raster joins; digitization corners; lithologic contacts, dikes, and radiometric variation; survey line/terrain-clearance artifacts; erosional scarps. A linear geophysical edge is not enough to establish displacement.
